1. PRD / SRS (Product Requirements & Software Specification) ↑ Kembali ke Daftar

Konteks & Pernyataan Masalah (Problem Statement)

Yayasan Satriabudi Dharma Setia (YSDS) membutuhkan platform manajemen penerbitan berkala ilmiah mandiri yang mendukung riset genomik, kedokteran presisi, dan jejaring laboratorium di Indonesia. CMS biasa (WordPress) tidak memiliki tata kelola peer review ilmiah, sedangkan platform monolitik lawas (OJS konvensional) sulit dikustomisasi dengan standar visual modern IGNITE. IGNITE hadir sebagai workflow-driven publishing platform yang diaudit ketat.

Sasaran & Metrik Keberhasilan Terukur (Success Metrics)

Kategori Metrik Indikator Kinerja Target Sasaran Metode Pengukuran
Leading Indicator Penyelesaian Form Submission > 85% draf disubmit tuntas tanpa hambatan wizard Log transisi status draft ke submitted
Leading Indicator Respon Undangan Reviewer Rata-rata < 72 jam untuk konfirmasi kesediaan review Selisih waktu undangan dikirim vs respons di reviewer_assignments
Leading Indicator Performa Web Publik (TTFB) TTFB < 200 ms dan Skor LCP < 1.5 detik Lighthouse & Laravel Pulse profiling
Lagging Indicator Siklus Review Naskah (Turnaround) Keputusan pertama rata-rata < 21 hari kerja Log riwayat naskah di submission_histories
Lagging Indicator Kepatuhan Pengindeksan Sitasi 100% artikel terbit memiliki metadata Crossref XML valid Uji skema XML Crossref & meta tags Google Scholar

Ruang Lingkup Luar (Non-Goals v1)

  • API Plagiarisme Otomatis Berbayar: Pengecekan kemiripan dilakukan manual oleh redaksi dan hasilnya diunggah sebagai lampiran pendukung.
  • Payment Gateway APC Otomatis: Pembayaran biaya artikel dikelola melalui invoice administratif terpisah.
  • Konversi Otomatis Full-text JATS XML: Output publikasi v1 difokuskan pada berkas PDF Galley dan halaman web metadata lengkap.

Matriks Peran Pengguna (RBAC Matrix)

Sistem menerapkan 10 peran hierarkis berbasis spatie/laravel-permission:

Super Admin

Pengaturan global server, instalasi modul, manajemen izin, dan pemeliharaan platform.

Journal Manager

Konfigurasi master data jurnal, nomor ISSN/e-ISSN, susunan dewan editor, dan pedoman kepenulisan.

Editor in Chief

Otoritas keputusan akademik final (Accept/Reject), penugasan Section Editor, dan persetujuan penerbitan.

Section Editor

Desk review awal naskah masuk, penunjukan mitra bestari, dan pemantauan putaran review.

Reviewer (Mitra Bestari)

Penilaian kritis naskah anonim, pengisian rubrik evaluasi, dan rekomendasi ilmiah.

Author (Penulis)

Pengajuan naskah baru via 5-step wizard, penelusuran status, dan pengunggahan perbaikan naskah.

Copyeditor & Proofreader

Penyelarasan gaya bahasa ilmiah dan pengecekan akhir berkas cetak coba PDF Galley.

Production Admin & Reader

Penjadwalan naskah ke Issue/Volume, ekspor DOI XML, dan pembacaan artikel publik.

2. SAD (System Architecture Document) ↑ Kembali ke Daftar

IGNITE dibangun dengan pendekatan Modular Monolith (HMVC) di atas Laravel 12. Pendekatan ini menggabungkan kecepatan pengiriman monolitik dengan isolasi domain yang bersih antar modul bisnis.

Struktur Direktori Anatomi Modul

Setiap modul dalam direktori Modules/ memiliki struktur independen:

Modules/[NamaModul]/
├── app/
│   ├── Http/Controllers/       # Web & REST Controllers
│   ├── Http/Requests/          # Form Request Validation
│   ├── Models/                 # Eloquent Models & Traits (SoftDeletes, Userstamps)
│   ├── Services/               # Business Logic & Service Layer
│   └── Providers/              # Module Service Providers
├── database/
│   ├── migrations/             # Skema tabel modul
│   └── seeders/                # Seeder data awal
├── resources/views/            # Blade Templates UI
├── routes/web.php              # Definisi rute web
└── module.json                 # Metadata modul

Skema database memisahkan secara tegas antara entitas proses workflow (submission, review rounds, decision) dan entitas hasil publikasi (issues, articles).

Kamus Data Entitas Kunci (Data Dictionary)

Tabel Basis Data Kolom Utama Tipe Data & Relasi Fungsi Bisnis

4. API & Route Documentation ↑ Kembali ke Daftar

Rute web dan endpoint AJAX dilindungi oleh middleware otentikasi dan otorisasi granular berbasis permission:

Metode URI Endpoint Controller & Aksi Middleware / Guard Keterangan
GET /submissions/create SubmissionsController@create auth, role:author Halaman 5-step wizard pengajuan naskah baru.
POST /submissions SubmissionsController@store auth, role:author Validasi form request & penyimpanan naskah draf/submit.
GET /editor/submissions EditorSubmissionsController@index auth, permission:submissions.review Dashboard editorial inbox (Server-side DataTable).
POST /editor/submissions/{id}/assign-reviewer EditorSubmissionsController@assignReviewer auth, permission:submissions.assign Penugasan reviewer dan pengiriman email ber-token.
GET /reviewer/workspace/{token} ReviewerWorkspaceController@show throttle:60,1 Akses telaah naskah aman bagi reviewer.
POST /reviewer/workspace/{id}/submit-review ReviewerWorkspaceController@submitReview auth, role:reviewer Pengiriman rubrik evaluasi skor dan komentar.
GET /issues/{id}/export-crossref-xml IssueService@exportCrossrefXml auth, permission:issues.publish Generator unduh berkas XML resmi Crossref untuk DOI.
GET /api/locations/cities?province_id=... LocationController@getCities auth Dropdown wilayah bertingkat dinamis (Prov/Kota/Kec).

5. Developer & Contribution Guide ↑ Kembali ke Daftar

Standar koding memastikan seluruh developer yang berkontribusi pada repositori IGNITE mengikuti konvensi arsitektur yang seragam:

Standar Koding PHP

Wajib mematuhi PSR-12 dan menerapkan strict type declarations. Logika bisnis berat dilarang diletakkan di Controller; wajib menggunakan Service Layer Pattern.

Konvensi Commit Git

Gunakan format Conventional Commits:
feat(submissions): add multi-step wizard
fix(issues): resolve crossref xml validation error
test(review): add unit tests for reviewer assignment

Perintah Artisan Modul

Membuat modul baru:
php artisan module:make [NamaModul]
Menjalankan migrasi modul tertentu:
php artisan module:migrate [NamaModul]

7. Deployment & Infrastructure Guide ↑ Kembali ke Daftar

IGNITE mendukung containerization penuh menggunakan Docker Compose untuk lingkungan pengembangan lokal maupun server produksi:

Service Container Image Base Port Mapping Peran Operasional
app Custom PHP 8.3 FPM Alpine Internal Container pemrosesan logika backend Laravel.
web Nginx 1.27 Alpine 8000:80 (Web) Reverse proxy web server dan static files.
db-postgres PostgreSQL 15 Alpine 5432:5432 Basis data relasional utama untuk produksi riset.
redis Redis 7 Alpine 6379:6379 In-memory cache store dan broker antrean background jobs.
queue Custom PHP 8.3 Worker Internal Worker pemroses email notifikasi asinkron (queue:work).
scheduler Custom PHP 8.3 Cron Internal Cron scheduler berkala (schedule:work) pengingat SLA review.

Checklist Rilis Produksi:

  1. Jalankan optimasi cache: php artisan config:cache && php artisan route:cache && php artisan view:cache.
  2. Pastikan symlink penyimpanan aktif: php artisan storage:link.
  3. Jalankan migrasi aman: php artisan migrate --force.
  4. Aktifkan process monitor Supervisor untuk memastikan container queue worker selalu hidup.

8. Security Hardening Runbook ↑ Kembali ke Daftar

Buku petunjuk pengerasan keamanan server operasional IGNITE mencakup proteksi firewall, enkripsi data, dan mitigasi serangan:

Firewall CSF / LFD

Otomatisasi via skrip server-hardening-csf.sh: blokir serangan brute-force SSH, port scanning, dan banjir koneksi SYN flood secara otomatis pada tingkat kernel OS.

Otentikasi Ganda 2FA

Wajib diaktifkan untuk peran Editor in Chief, Section Editor, dan Admin menggunakan standar RFC 6238 TOTP untuk mencegah pengambilalihan akun redaksi.

Isolasi Penyimpanan Berkas

Berkas naskah dalam tahap review disimpan pada disk privat terenkripsi. Akses unduh diwajibkan melewati controller berotorisasi, bukan tautan berkas statis publik.

Throttling & Sanitasi Input

Pembatasan percobaan login maksimal 5x per menit. Seluruh masukan form dibersihkan via Form Request Validation untuk menangkal injeksi SQL dan XSS.

9. User Manual & Standar Operasional Prosedur (SOP) Sistem ↑ Kembali ke Daftar

Panduan langkah-demi-langkah bagi seluruh aktor dalam menjalankan siklus penerbitan naskah ilmiah:

Rangkuman 11 Standar Operasional Prosedur (SOP)

1

SOP Penulis — Pengajuan Naskah Baru (Wizard 5 Langkah)

Penulis memilih jurnal, mencentang checklist etika, mengisi metadata abstrak/kata kunci, mendaftarkan rekan penulis (*Co-Authors*), mengunggah berkas naskah asli beserta berkas anonim (*Anonymized*), dan mengonfirmasi pengiriman.

2

SOP Penulis — Penanganan Putaran Revisi

Penulis mengunduh catatan telaah reviewer, menyusun tabel *Response to Reviewers* (Komentar vs Jawaban per butir), dan mengunggah berkas perbaikan bertanda *Track Changes*.

3

SOP Mitra Bestari — Konfirmasi Undangan & Telaah Sejawat

Reviewer merespons undangan dalam 72 jam, mengunduh naskah anonim, mengisi rubrik evaluasi 4 parameter, menulis masukan untuk penulis, serta memberikan rekomendasi rahasia ke editor.

4

SOP Dewan Redaksi — Desk Review & Penunjukan Reviewer

Section Editor menyaring naskah masuk dalam batas waktu 5 hari kerja, menunjuk minimal 2 reviewer non-afiliasi yang kompeten, dan memantau batas waktu telaah (14 hari).

5

SOP Pemimpin Redaksi — Keputusan Editorial & LoA

Editor in Chief menelaah kesimpulan reviewer dan menetapkan keputusan: *Request Revision*, *Accept Submission* (otomatis menerbitkan Surat Tanda Diterima / LoA), atau *Reject*.

6

SOP Tata Letak & Produksi — Galley Proof & Publikasi Issue

Tim tata letak menyelaraskan bahasa, menyusun PDF Galley, melakukan proofreading bersama penulis (48 jam), menjadwalkan ke Issue aktif, dan mengekspor Crossref XML untuk aktivasi pengenal DOI permanen.
